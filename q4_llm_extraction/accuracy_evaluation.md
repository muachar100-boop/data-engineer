# Q4 准确率评估

## 结论

最终流程是 rules_v8，加上 v8 Prompt + gpt-4o-mini，再用 gpt-4.1-mini 兜底。在两批独立样本（W01–W30、X01–X30，共 60 条模型路由评论）上，按评论计的结果如下：

| 指标 | 最终流程（v8 + 4o-mini） | 对照（v6 + 4.1-mini） |
|---|---:|---:|
| 类别集合完全一致 | 34/60 = 57%（95% CI 44–68%） | 37/60 = 62% |
| 类别 + 逐类严重度 | 31/60 = 52% | 36/60 = 60% |
| 情绪档位一致（5 档） | 47/60 = 78%（66–87%） | 48/60 = 80% |
| 可行动性 | 56/60 = 93%（84–97%） | 54/60 = 90% |
| **四字段同时一致** | **23/60 = 38%（27–51%）** | **29/60 = 48%** |

- 区间是 Wilson 95% 区间。每批只有 30 条，**只能识别明显差异**。
- 最终流程在情绪和可行动性上和对照持平，**类别明显更弱**。这是为了把成本压到 $3 以内主动接受的下降，取舍见 `cost_report.md`。
- 这些是**模型路由（占全部行的 62%）**的结果，不是全量准确率。规则路由的结果另外列在下面。

## 方法：没有 ground truth 时怎么评

1. **先封存标签，再看模型输出。** 每批先抽样、标注、记录哈希（W、X 两批见 `evaluation/<批次>/sealed_labels_manifest.json`），然后才发请求。评估脚本会核对哈希，标签在封存后被改过就拒绝运行。
2. **判定规则在运行前登记。** 门槛和判定方式在运行前写入计划文件，状态是 `registered`，之后不改（W、X 两批的原文见 `evaluation/<批次>/decision_rule.json`）。结果不满意也不事后改门槛，要改只能换一批新样本。
3. **样本互相独立。** 每批固定随机种子，按文本长度四分位分层抽样，并按标准化文本排除以前所有批次（S、H、V、W、X 和探针 P）的重复内容。用来调过 Prompt 的样本就算开发数据，不再拿来声称“独立测试”。
4. **同一批样本上放一个对照组。** 对照是 v6 + gpt-4.1-mini，用的样本和后处理都和候选一样，看的是候选和对照的差距，而不是只看绝对分数。
5. **严格指标与人工接受分开报告。** 严格指标逐字段对比：类别集合、每个类别的最高严重度、情绪档位、可行动性。人工接受（审核人认为可以接受）单独列出，不混进严格指标。
6. **证据和翻译用程序硬校验。** 每个 evidence_quote 都必须是原标题或原正文中连续的一段。全量 22,475 条输出全部通过；没通过的 18 条进了死信，没有输出。英文翻译是否忠实只能人工判断，不能由程序证明。

### 抽样设计的数据依据

抽样方案来自调用模型之前做的数据检查（分流统计见 `cost_report.md`）：

- **分路径抽样。** 规则路径和模型路径的难度完全不同，所以分开抽、分开报告。第一批开发集和 H 批覆盖了规则、空文本和模型三条路径；之后的 V、W、X 批只抽模型路径，因为质量差异集中在这里。分层样本的平均分不能直接当作全量准确率。
- **刻意覆盖难例。** 开发集刻意加入了否定（“não veio com defeito”）、多问题、标题和正文矛盾、重复文本这几类样本。检查时约有 1,369 行同时命中两类以上问题关键词，但关键词命中不等于真的有多个问题：“caixa” 可能指音箱而不是包装，“qualidade” 也可能是在夸，“apenas” 不一定表示缺件。所以多问题能否抽全只能靠人工标签来判断，不能靠关键词统计。
- **低评分不等于有问题。** 低评分里有 “bom”“excelente” 这样的正面短评，标签允许 issues 为空，评分只作背景，不作为问题证据。

## 各批样本的结果

| 批次 | 用途 | 标签 | 主要结果 |
|---|---|---|---|
| S01–S30 | 开发回归（v2–v6 反复调优） | 人工 | v6 30/30。**不是独立结果** |
| H01–H30 | v6 独立验证（第三轮） | 人工，证据和翻译由 AI 辅助 | 规则 10 条：类别 10/10，严格四字段 3/10，人工接受 9/10；模型 20 条：类别 14/20，严格四字段 8/20，人工接受 14/20 |
| H11–H30 | 换模型小试 | 同上 | v6 + 4o-mini：四字段 4/20（4.1-mini 是 8/20），没有通过 |
| V01–V30 | v7（9 档情绪） | AI 辅助人工审核 | v7 + 4o-mini 情绪 13/30，对照 19/30。4o-mini 打分过重，**没有通过** |
| W01–W30 | v8（5 档保守情绪） | 审核人确认了 Claude 的建议，没有改动 | 情绪 23 vs 24，四字段 10 vs 12，类别 14 vs 16。登记的门槛要求情绪比对照多 3 条，**没有通过** |
| X01–X30 | v10 非劣效验证 | 同上 | 情绪 24 vs 24，类别 20 vs 21，**四字段 13 vs 17，没有通过**（门槛是不低于对照 − 2） |

**最终流程按登记规则并没有通过 X 批的非劣效门槛。** 最后还是选用它，是因为在 $3 预算内找不到质量更好的方案：v6 + 4.1-mini 全量约 $4.4，降本到极限也还需要约 $3.2。这是用户在知道这个风险的前提下做的取舍，不是验证通过的结论。

## 主要错误类型（W、X 批中 4o-mini 与对照结果不同的样本）

| 类型 | 例子 | 说明 |
|---|---|---|
| 多标 seller_communication | X05、X24、W05、W19：只是没收到货 | 全量中 seller_communication 有 2,315 条，很可能偏高 |
| 主观质量判成缺陷 | X03 “qualidade muito aquém da descrição” → quality_defect | 应为 other/low |
| 多问题评论漏标类别 | W01、W17、W23、X18、X26 | 只抽了一部分问题，或者干脆判成没有问题 |
| 情绪偏重 | W03、W26、X10、X25 | 普通投诉给了 -1，v8 的保守规则仍没有完全纠正 |

另外有两类问题和用哪个模型无关，需要单独说明：
- **改写原文。** X28 中，4.1-mini 两次把 “mandei” 写成 “mande”；H26 中，4o-mini 把同一批另一条评论的句子当成了证据。这些都被引句校验拦下，经修复、兜底或死信处理，没有进入输出。
- **全量死信 18 条。** 其中 15 条是引句不合格，2 条是重复问题，1 条是 review_id 抄错。这 18 条没有输出，覆盖率为 99.92%。

## 规则路由

规则路由共 8,610 行，其中 8,141 行情绪为 0（主要是空文本或纯符号），其余是完整短语，例如 “ruim”、“Produto errado”。

H01–H10 是在 v6 情绪值下评的：类别 10/10，人工接受 9/10，严格情绪只有 3/10，主要因为规则情绪值的颗粒度比人工标签粗。之后 rules_v8 把规则的情绪值映射成了 5 档（例如 péssimo、muito ruim → -1，ok、bom → 0.5），**但这个映射还没有在独立样本上验证过**。

## 局限

1. **标签不是完全独立的人工盲标。** H 批的证据和翻译由 AI 辅助整理。V 批是审核人在附带 AI 建议的表格里确认的。W 和 X 两批的 60 条标签审核时都没有改动，所以它们实际上是 Claude 依据原文、v8 量表和 v6 类别规则做出的判断，再经审核人确认。情绪和严重度本身没有唯一的客观答案。
2. **标签的标准对对照组不利。** 标签按 v8 情绪量表标注，候选组也使用 v8 Prompt，所以情绪一项天然偏向候选组；即便如此，候选组也只和对照组持平。
3. **样本量小。** 每批 30 条只能识别明显差异，60 条合并后，四字段的 95% 区间仍有约 ±12 个百分点。
4. **只在独立样本上抽查。** 全量 13,898 个模型输入里，只有分层抽出的这 60 条有人工标签。按长度分层不保证覆盖低频类别（例如 packaging），各类别的召回率无法可靠估计。
5. **多问题评论只比较类别集合。** 同一类别下有多个事件时，不评估是否都抽全了。

## 复现

```bash
python q4_llm_extraction/evaluation/evaluate.py --check
```

离线运行，不发 API 请求，只用 `evaluation/` 目录里的数据：W、X 两批的样本、封存标签、登记的判定规则，以及各组模型的最终输出。脚本会核对标签哈希，逐条校验输出仍然通过引句校验，然后重算上面“结论”表、W 和 X 两批的各组结果、X28 的三种处理方式以及 Wilson 区间。加 `--check` 时，会断言这些数字与本文档一致。

**可复现范围：** 只有 W、X 两批（结论的依据）可以在 main 上复现。S、H、V 三批和换模型小试是开发过程的历史结果，它们的原始数据和实验脚本没有纳入本仓库，所以在仓库里不能复现，只作为过程记录。
