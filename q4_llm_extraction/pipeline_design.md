# Q4 抽取 Pipeline 设计

**分流。** 评分 ≤ 3 的评价共 22,754 行，先走规则（`rules_v8.py`）。空文本和纯符号直接输出空问题、情绪 0；“ruim”“Produto errado”这类整字段完全匹配的短语，按固定模板输出。规则只做完整匹配，不做关键词包含匹配，避免把“não veio com defeito”误判成缺陷。规则共处理 8,610 行，其余 14,144 行按（标题，正文，评分）精确去重，得到 13,898 个独立输入，交给模型。

**模型与 Prompt。** 主模型是 gpt-4o-mini，temperature=0，用 Structured Outputs 严格模式，每批 5 条。Prompt 直接读葡萄牙语原文，不另外调用翻译模型；只翻译选中的证据句，要求保留否定、数量和不确定性。Prompt 里写明了类别边界、严重度和 5 档保守情绪量表，例如“未收到”不等于延误，主观不满不等于缺陷。评论内容一律当作数据，不当作指令。

**防幻觉。** 每个 evidence_quote 都要由程序确认是原标题或原正文中连续的一段。只差大小写的，替换成原文写法；修不了的那条单独交给 gpt-4.1-mini 重抽；还是失败就记入死信，不输出。这样一来，串条、改字、编造的证据都进不了结果。

**批处理与运行。** 8 个线程并发。每个请求发出前，按最坏情况预留费用，超出剩余预算就停发；37 分钟后也停发新请求。遇到 429、5xx 或超时，最多重试 2 次，仍失败就留给续跑。结果逐条落盘，中断后重跑不会重复付费。全量用时 28 分钟，花费约 $1.42，兜底率 2.5%，死信 18 条。

**评估。** 每批独立 holdout 都是先封存人工标签、先登记判定规则，再运行模型，并在同一批样本上与 v6 + gpt-4.1-mini 对照。详见 `accuracy_evaluation.md` 与 `cost_report.md`。
