# Q1.3 数据清洗策略

总原则：原始数据只读，清洗在派生层完成，保留与原始行的映射；缺失不盲填。金额 = 数量 × 单价，未核对支付前不称实付。

## 1. 按下游用途分别清洗

**A 销售报表：** 保留匿名记录（也是真实销售）。C 前缀取消、退款按带符号金额计入净额，正数量 C 记录单独待查。邮费、手续费等非商品代码分项列示，礼券单列，A 前缀坏账只进财务审计，均不混入商品销售。

**B 客户分群（RFM）：** 只用有 Customer ID 的商品销售，排除匿名、测试、费用、调整和零价记录。R 取最后有效购买日，F 按有效 Invoice 数，M 按正向销售金额；扣除已匹配退款的净额另存，全退客户保留并标记。

**C 商品推荐：** 排除匿名和非商品代码，按 StockCode 识别商品。取消、退货作为负反馈事件，降低原购买权重；赠品降权，批发大单单独建模。

## 2. 看起来脏但不该删的数据

- 缺失 Customer ID：占 22.77% 的行、13.68% 的净金额，删掉会低估销售额；
- C 前缀和负数量：是真实退款，删掉会高估净销售；
- 34,335 条整行重复：无法区分重复导入和真实重复下单，确认前保留并标记；
- 80,995、74,215 两笔极端大额：估计是录入错误后冲销，但原因未确认前保留并标记；确认后才成对删除，不能只删负向一笔；
- A 前缀坏账：不计入销售额，但要留作审计。

## 3. 有损操作及取舍

去重、删零价和测试记录、剔除匿名客户都会丢掉可能真实的交易或客户；退货匹配在多候选时也只是推断。我的标准是：能用数据证明是错误、或明确不属于该用途时才排除；不确定的先隔离、打标记；每一步记录影响的行数和金额，并披露客户覆盖损失。
